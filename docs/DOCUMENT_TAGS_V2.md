# Теги документов v2

Все новые шаблоны используют только имена из `ui/tag-schema.js`. Этот же справочник читается Python при заполнении DOCX. Старые имена не поддерживаются. Исходные загруженные DOCX и HTML не переписываются автоматически: приложение перечисляет неизвестные теги, после чего пользователь заменяет шаблон. Встроенные образцы уже переведены на v2.

## Карта по примерам АР-3 и КР-3

Номера страниц ниже — страницы присланных PDF. Это карта данных, а не подтверждение нормативной корректности исходных документов.

## Роли и реквизиты

Роли: `СтройконтрольЗаказчика`, `ПредставительСтроительства`, `СтройконтрольПодрядчика`, `Проектировщик`, `ИсполнительРабот`.

У организации доступны `Наименование`, `КраткоеНаименование`, `ИНН`, `КПП`, `ОГРН`, `Адрес`, `Телефон`, `Email`, `СРО`, `Реквизиты`. `Наименование` предпочитает полное, затем краткое. `КраткоеНаименование` — наоборот. `Реквизиты` соединяет только заполненные сведения.

Ранее введённое текстом название участника сохраняется. Реквизиты из справочника берутся автоматически только при единственном точном совпадении с полным или кратким названием. При совпадении нескольких организаций нужно выбрать конкретную по ID. Явно выбранная, но удалённая организация — ошибка при использовании её тега.

Для АИК используются `АИК.Номер`, `АИК.Дата`, `АИК.Материал`, `АИК.Количество`. Теги АОСР не заполняются данными АИК. `Документ.*` относится к текущей карточке независимо от её типа.

## Пустые значения и ошибки

Необязательные поля дают пустую строку. Изображение без значения отсутствует. Пустой список удаляет повторяемую строку таблицы, сохраняя заголовок. Требуемые поля перечислены в справочнике; проверяются только использованные шаблоном поля. Для штатной формы АОСР проверяются объект, номер, дата и работы.

Дополнительные поля всегда имеют префикс `ДопПоля.`. Совпадение двух нормализованных дополнительных имён — ошибка; системные теги нельзя перекрыть.

Подписанты выбираются из комплекта, назначенного акту. Если назначено несколько комплектов, используется выбранный том. Чужой комплект не применяется; при отсутствии однозначного выбора выдаётся объяснение.

## Проверки

`tests/test_document_tags.py` проверяет словарь всех штатных образцов, отсутствие неразрешённых тегов, подстановки в документе и колонтитулах, обязательные поля и отличие скалярного `Реестр.Текст` от повторяемых строк.

`tests/smoke_document_tags.py` проверяет в настоящем WebEngine независимость компании выпуска и пяти ролей, приоритет назначений, чужой и неоднозначный комплект, удалённого подписанта, даты, нулевые объёмы, места листов, 12 экранов и заполненный АОСР DOCX. Сценарий входит в обязательную Windows-сборку.

Остальные сценарии проверяют PDF, Word, рамки, ведомости, порядок приложений, историю, сохранение и восстановление. Word COM проверяется на Windows; интерфейсные тесты заполнения DOCX подменяют только сам конвертер Word.
