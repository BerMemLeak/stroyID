# Архитектура СтройИД

Приложение разделено на слои. `app.py` только запускает Qt или самопроверку.

| Каталог | Ответственность |
| --- | --- |
| `src/stroyid/domain` | Миграция предметной модели, общие теги документов |
| `src/stroyid/application` | Сценарии импорта материалов, формирования документов и экспорта |
| `src/stroyid/infrastructure/storage` | Текущие JSON-карточки, файлы, миграция старого формата |
| `src/stroyid/infrastructure/documents` | Word, оформление схем, автоматизация Word на macOS |
| `src/stroyid/presentation/desktop` | Окно Qt, WebChannel, маршрутизация нативных команд |
| `ui/src/core` | Состояние и обработка ввода |
| `ui/src/domain` | Выборки, проверки комплектности и состав томов |
| `ui/src/presentation` | Компоненты и представления |
| `ui/src/features` | Сценарии интерфейса, разделённые по функциям |

## Хранение

Единственный источник данных — текущие JSON-карточки. Служебный индекс хранит
их расположение, структуру полей и принадлежность. В индексе нет копий
содержимого карточек. Хеши текущего содержимого используются для проверки
изменений, а не для сохранения версий.

`CardCodec` собирает дерево предметной модели, `CardLayout` определяет имена
карточек и файлов. `FileTransaction` сначала подготавливает всю запись,
проверяет контрольные суммы и применяет её. Журнал существует только до
завершения операции; после сбоя следующий запуск завершает начатую запись.
`EmptyDirectoryCleaner` удаляет только пустые прежние каталоги, повторяя
операцию после временной блокировки. Посторонние файлы сохраняются.

Перед переименованием объекта Qt освобождает наблюдение за прежним деревом
каталогов. После записи наблюдение устанавливается заново, включая случай
ошибки сохранения.

`legacy.py` читает прежний формат без создания версий. Текущие файлы проверяются
до переноса. История удаляется только после записи текущей базы. Незавершённая
очистка помечается в индексе и повторяется при следующем запуске.

## Экспорт

Снимок — отдельный сценарий приложения: проверка и формирование PDF,
экспорт независимо открываемой базы с используемыми справочниками, проверка
ZIP, затем публикация готового файла. Ошибка до последнего шага не затрагивает
существующий архив. В рабочей базе снимки не накапливаются.

## Интерфейс и сборка

HTML содержит оболочку. Исходники из `ui/src` собираются по явному списку
`ui/sources.json` скриптом `tools/build_frontend.py`. Итоговый пакет сохраняется
в `ui/dist/app.js`; Node и npm при пользовательской сборке не нужны.
Общий контекст интерфейса сохранён для совместимости существующих редакторов.

WebChannel принимает JSON и возвращает результат. Таблица `DesktopCommands`
направляет каждую операцию в отдельный обработчик; бизнес-операции хранения,
импорта и экспорта вынесены из транспорта. Изменение форматов хранения следует
сопровождать проверками миграции, сохранности вложений и повторного открытия.
